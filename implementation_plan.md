# Implementation Plan: Jandarpan CodeCraft-First + Search-Demand Engine

This document outlines the proposed implementation plan to transform the Jandarpan newsroom from a provider-fragile, geographically hardcoded system into a **CodeCraft-first, Search-Demand-Driven Global Autonomous Newsroom**.

## Goal Description
Perform an end-to-end migration of the Jandarpan AI Newsroom pipeline. 
- Replace Gemini as the primary editorial provider with CodeCraft.
- Introduce a real Search-Demand Engine to prioritize generated content (optimizing for traffic and legitimate SEO value over raw volume).
- Prevent silent provider fallbacks (e.g., to OpenAI).
- Halt the publication of raw fallback drafts and bypasses like `batch_rescue`.
- Simplify the article state machine and ensure all configurations are global-ready.

## User Review Required

## Proposed Changes

### 1. CodeCraft-First Architecture (`src/lib/ai/providers`)
- **[NEW] `codecraft.ts`**: Implement the CodeCraft provider adapter. It will check `CODECRAFT_API_KEY`, allow overrides via `CODECRAFT_EDITORIAL_MODEL` and `CODECRAFT_REPAIR_MODEL`, and handle 402 Exhausted and rate limits.
- **[MODIFY] `router.ts`**: Replace the `WRITER_CHAIN` default from `["gemini", "groq", "openrouter", "openai"]` to `["codecraft"]`. Emergency fallbacks will be stripped from the normal chain to prevent infinite waterfalls.
- **[MODIFY] `chat.ts`**: Register CodeCraft in the chat completion router.
- **[MODIFY] `quota.ts`**: Add accurate token accounting and concurrency tracking for CodeCraft.

### 2. Simplify Editorial State Machine (`src/lib/news/ai/`)
- **[MODIFY] `generate-article.ts`**: 
  - Eradicate endless retry loops.
  - Implement strict 8-step pipeline: Fact Pack -> CodeCraft -> Validate -> (if fail) Repair Once -> Validate -> (if fail) `REJECTED`.
  - **Crucial**: Remove any ability for `buildFallbackDraftFromFactPack` to be marked as `PUBLISH_READY`.
- **[MODIFY] `pipeline/batch-rescue.ts`**: Remove the aggressive batch rescue logic that bypasses quality gates to publish failed drafts.

### 3. Global Content & Search Demand Engines (`src/lib/news/`)
- **[NEW] `search-demand.ts`**: Worker logic to fetch search opportunities (from GSC, trends, etc.), calculate the normalized `opportunityScore`, and map queries to Search Intents.
- **[MODIFY] `config.ts`**: Remove hardcoded "Chhattisgarh" assumptions. Introduce a configurable taxonomy (`country`, `state`, `region`, `topic`). Chhattisgarh will be set as the initial strong priority, but configurable via environment variables (`NEWSROOM_GLOBAL_MODE=true`).
- **[MODIFY] `events.ts`**: Fuse `News Event + Search Opportunity = Editorial Opportunity`.

### 4. Database Schema Updates (`supabase/migrations/`)
- **[NEW] `migration.sql`**: Add the following tables with proper RLS policies and indexing:
  - `search_opportunities`
  - `search_queries`
  - `topic_clusters`
  - `editorial_candidates`
  - Modify `articles` to track strict AI states (`DEFERRED_QUOTA`, `FAILED`, `PUBLISH_READY`, etc.)

### 5. Observability and Health
- **[MODIFY] `health.ts`**: Prevent blind `return { critical: false }`. Honestly report CodeCraft connection, queue depth, dead letters, and quota status.
- **[MODIFY] `admin/dashboard/`**: Add internal telemetry fields for CodeCraft budget, success rates, top search opportunities, and exact failure classifications.

## Verification Plan
1. **Test A (CodeCraft Connectivity)**: Ensure CodeCraft responds correctly and records token usage.
2. **Test C (Quality Failure & Repair)**: Inject a bad fact pack, verify it fails, attempts a single repair, fails again, and correctly sets state to `REJECTED` (not rescuing).
3. **Test D (Provider Quota)**: Simulate a CodeCraft 402/429 response. Verify the state becomes `DEFERRED_QUOTA` and no retry storm is created.
4. **Test I & J (End-to-End)**: Allow a real candidate to pass, get generated by CodeCraft, pass validation, and be visible in the canonical DB/Homepage.
